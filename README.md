# رشيد (Rasheed AI)

مساعد ذكي لترشيد استهلاك الطاقة والمياه في المنازل السعودية.

> **نموذج تجربة أولي (Experience Prototype)** — الواجهة كاملة وتفاعلية، والحسابات محلية
> وحتمية. لم تُربط بعد بـ Gemini Vision أو واجهات الطقس والتعرفة الرسمية.

## الفكرة

رشيد لا يكتفي بعرض نصائح عامة للترشيد. الفكرة الأساسية:

> **«أرني كيف يؤثر تغيير سلوكي على فاتورتي بالريال السعودي.»**

الرحلة الكاملة:

```
الفاتورة → التحليل → أين يذهب استهلاكك → فرص التوفير
        → خطة رشيد → ماذا لو؟ → الفاتورة المتوقعة
```

## أبرز ما يعرضه النموذج

- **رفع الفاتورة** — سحب وإفلات، معاينة، إزالة. الملف لا يغادر الجهاز.
- **تحليل مباشر** — توزيع تقديري للاستهلاك على مخطط دائري تفاعلي.
- **فرصة التوفير** — مقارنة بصرية بين الفاتورة الحالية والمتوقعة.
- **خطة رشيد** — ثلاث خطوات، قيمة كل واحدة بالريال.
- **«ماذا لو؟»** — ثلاثة مؤشرات تحدّث الفاتورة فورًا مع حركة سلسة للأرقام.
- **قسم المياه** — استهلاك شهري وفرص ترشيد، إلى جانب الكهرباء.

## أرقام السيناريو التجريبي

منزل في الرياض، فيلا، 6 أفراد، 5 مكيفات، 30 يومًا، حرارة 43 درجة مئوية.

| البند | القيمة |
| --- | --- |
| الفاتورة الحالية | 620 ريال · 2,450 ك.و.س |
| مع خطة رشيد | ≈ 485 ريال · 1,908 ك.و.س |
| التوفير المحتمل | ≈ 135 ريال شهريًا (22٪) |
| فاتورة المياه | 180 ريال · 35 م³ |

## البنية

```
app/                     الصفحة الجذر، التنسيقات العامة، الأيقونة
components/
  AppShell.tsx           آلة حالة الرحلة (واجهة ← رفع ← تحليل ← لوحة)
  landing/               الصفحة التعريفية
  invoice/               رفع الفاتورة
  analysis/              شاشة التحليل والمخطط الدائري
  dashboard/             لوحة النتائج الرئيسية
  savings/               خطة رشيد
  simulator/             محاكي «ماذا لو؟»
  water/                 قسم المياه
  layout/ ui/            الهيكل والمكوّنات المشتركة
data/                    البيانات التجريبية (منزل، فاتورة، تحليل)
lib/
  simulation.ts          محرك المحاكاة الحتمي
  formatting.ts          تنسيق الأرقام والوحدات بالعربية
```

### قاعدتان في البنية

1. **لا قيم مكتوبة داخل الواجهات.** كل البيانات في `data/`، وكل الحسابات في
   `lib/simulation.ts`. استبدال المصدر الحقيقي لاحقًا لا يتطلب تعديل الواجهات.
2. **مصدر واحد للأرقام.** قيم التوفير في خطة رشيد تُحسب من محرك المحاكاة نفسه
   تتابعيًا، فلا يتكرر احتساب التوفير ويبقى مجموع البنود مساويًا لتوفير الخطة.

## نموذج المحاكاة

نموذج حتمي مبسّط، غرضه توضيح فكرة المنتج لا محاكاة خوارزمية الفوترة الرسمية:

```
التبريد      = المرجعي × (الساعات ÷ 18) × (1 − 0.066 × (الحرارة − 24))
تسخين المياه = المرجعي × (0.15 + 0.85 × الساعات ÷ 6)
باقي الأجهزة = ثابت
الفاتورة     = الاستهلاك × 0.249 ريال + 10 ريال رسوم ثابتة
```

معاملات النموذج والتعرفة معايَرة لتطابق أرقام السيناريو التجريبي.

## الخطوات القادمة

- ربط قراءة الفاتورة بـ **Gemini Vision**
- استدعاء الوظائف (**Function Calling**) لجلب الطقس والتعرفة الرسمية
- استبدال `lib/simulation.ts` بمحرك الحساب الحقيقي
- محاكي تفصيلي لاستهلاك المياه
